# 브라우저 렌더링 5단계

## 왜 중요한가?

브라우저 렌더링 과정의 흐름과 각 단계 별 특징을 알고 있지 않으면

- 렌더링 성능에 좋지 않은 방식으로 웹 페이지를 구현할 수 있다.
- 즉, 사용자가 모든 콘텐츠가 표시된 웹 페이지를 보는데 오래 걸릴 수 있고
- 이는 사용자 경험에 부정적인 영향을 준다.

## 실제 동작

1. HTML 파싱 → DOM 생성
2. CSS 파싱 → CSSOM 생성
   - 스타일 우선순위(cascade) 계산
3. DOM + CSSOM → Render Tree 생성
   - 화면에 보이는 요소만 포함
   - `display: none`은 제외됨
4. Layout
   - 각 요소의 위치/크기 계산
   - 트리 구조 기반 계산 → **Layout(reflow)은 비싸다**
5. Paint
   - 픽셀로 화면에 그림

## 그래서 어떻게 코딩해야 하나?

### Reflow 최소화

- DOM 조작을 여러 번에 나눠서 하지 않는다.
- 한 번에 묶어서 처리한다.
- Layout을 반복적으로 유발하지 않는다.

### React가 가상 DOM을 쓰는 이유와 연결

- DOM 직접 조작하지 말고
- 메모리에서 먼저 계산하고
- 최소 변경만 반영한다.

### 정리

DOM 변경은 layout을 발생시킬 수 있고 이는 비용이 크기 때문에, 조작을 줄이거나 한 번에 처리함으로써 reflow를 최소화한다. React의 가상 DOM도 실제 DOM 변경을 최소화하기 위한 전략이다.

## 한 문장 정리

브라우저는 DOM과 CSSOM을 결합해 Render Tree를 만들고, Layout과 Paint 과정을 거쳐 화면에 그린다.
